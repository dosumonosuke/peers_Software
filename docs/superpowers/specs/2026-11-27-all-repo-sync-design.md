# 全リポジトリ同期アプリ 設計書

- 作成日: 2026-11-27
- 状態: 下書き（ユーザー確認待ち）
- 仮の名前: **peers Sync**（あとで変えてOK）

> この設計書のなかで「**（Claudeの判断）**」と書いてある部分は、ユーザーが決めたことではなく、Claude が提案として決めたものです。違うと思ったら遠慮なく変えてください。

---

## 1. 何のためのソフトか（目的）

どのパソコンでも、同じ作業の続きができるようにしたい。

ユーザーはいま、GitHub に 11 個のリポジトリを持っている（kinoko_vs_takenoko、muscle_app、hololive、Youtube_TikTok_X_ALL_app、Criminal_story、rekish、enkakusousa、youtube-tiktok、TEST、desktop-tutorial、peers_Software）。中身はプログラム、画像、動画、AI に読ませるための `.md` ファイルなど。

ただし Git の操作（コミット、プッシュ、フェッチ、プルなど）はまだ慣れていない。そのため、**ボタンを 1 回押すだけで、すべてのリポジトリが GitHub と同期する**ソフトを作る。

### 成功の基準

- パソコン A で作業してボタンを押す。そのあとパソコン B でボタンを押すと、B に A の作業がそのまま出てくる。
- 新しいパソコンでも、ログインしてボタンを押すだけで全リポジトリがそろう。
- ユーザーが Git のコマンドを 1 つも打たなくていい。
- 作業が消えない。何が起きても、最悪でも「同期できませんでした」で止まる。

## 2. やること / やらないこと / やってはいけないこと

### やること（ゴール）

1. GitHub アカウントにある**全リポジトリ**（公開・非公開の両方）を対象にする。
   - **（Claudeの判断）**「全リポジトリ」とは、ユーザー本人が持っているリポジトリのこと。アーカイブ済み（読み取り専用）のリポジトリは対象外にする。
   - 他の人のリポジトリや組織のリポジトリは、設定画面で追加したときだけ対象にする。
2. ボタン 1 つで、リポジトリごとに次を自動で行う。
   - そのパソコンにないリポジトリは**クローン**（ダウンロード）する。
   - 手元で変更があれば、**コミット**（セーブ）して**プッシュ**（GitHub に送る）する。
   - GitHub 側に新しい変更があれば、**プル**（取り込む）する。
3. 動画などの大きいファイルは **Git LFS** で扱う。この設定もアプリが自動で行う。
4. Windows と Mac の両方で動く。
5. 何をしたかを、やさしい日本語で画面に表示する（例：「muscle_app: 3 個のファイルをセーブして GitHub に送りました」）。

### やらないこと（今回は作らない）

- ボタンを押さなくても勝手に同期する機能（自動同期・定期同期）。将来の追加候補にする。
- リポジトリの外にあるファイル（デスクトップのファイルなど）の同期。
- GitHub 上に新しいリポジトリを作る機能。将来の追加候補にする。
- ブランチの作成や切り替え。アプリは「いまそのパソコンで開いているブランチ」だけを同期する。
- すでに GitHub に入っている大きなファイルを LFS に移しかえること（履歴の書きかえは危険なのでやらない）。
- LFS の無料枠の残りを正確に表示すること。

### やってはいけないこと（こうなったら失敗）

- **ユーザーの作業を消す・上書きする**こと。具体的には次の 3 つは絶対にやらない。
  - 強制プッシュ（`git push --force`）
  - `git reset --hard`
  - 手元の未セーブの変更を捨てること
- 2 台のパソコンで同じファイルを別々に変えたとき（**競合**）に、どちらかを黙って捨てること。
- パスワードやトークンを、ファイルに平文で保存すること。
- 1 つのリポジトリで失敗しただけで、ほかのリポジトリの同期まで止まること。

## 3. 前提と制約

- **GitHub の制限**（2026-11 時点の公式ドキュメントより）
  - 普通の Git では、100MB を超えるファイルはプッシュできない。
  - Git LFS は無料プランで容量 10GB、ダウンロードは月 10GB まで。1 ファイルは 2GB まで。
  - → 動画が多いと無料枠を超える可能性がある。ユーザーはそれを分かったうえで A 案（全部 GitHub）を選んだ。
- ユーザーは Git の初心者。エラーメッセージは英語の Git の文章をそのまま見せず、日本語で「何が起きたか」「どうすればいいか」を表示する。
- 各パソコンには Git（と Git LFS）が入っている必要がある。入っていなければ、アプリがそう伝えて、インストールのページを案内する。

## 4. 作り方の候補（Approaches）

| 案 | 内容 | 良いところ | 弱いところ |
|---|---|---|---|
| **A（採用）** | 全部 GitHub で同期する。動画は Git LFS に入れる | 使うサービスが 1 つでシンプル。Git の勉強にもなる | 動画が増えると LFS の無料枠（10GB）を超える |
| B | コードと `.md` は GitHub、画像・動画は Google Drive などのクラウドドライブ | 動画が何十 GB でも大丈夫 | 設定が増え、仕組みも複雑になる |
| C（除外） | GitHub を使わず、フォルダごと Dropbox などで同期する | 仕組みが一番かんたん | Git の管理ファイルが壊れやすい。GitHub を覚えたいという目的にも合わない |

**ユーザーは A を選んだ。** 理由はシンプルさと、GitHub を使い慣れたいという目的に合うから。将来、動画が増えて無料枠が足りなくなったら B に広げる余地を残しておく（第 7 章）。

## 5. 決まっていること（どう作るか）

### 5.1 画面

画面は 1 つだけ（**Claudeの判断**）。

```
┌──────────────────────────────────────────┐
│  peers Sync                  [設定] [?]   │
│                                          │
│        ┌──────────────────────┐          │
│        │     🔄  ぜんぶ同期     │          │
│        └──────────────────────┘          │
│   最後の同期: 今日 14:32（このパソコン）      │
│                                          │
│  ✅ muscle_app        セーブして送信 (3)    │
│  ✅ hololive          最新を取り込み (5)    │
│  ⬇️ Criminal_story    新しくダウンロード     │
│  ⚠️ rekish            競合あり → 確認する   │
│  ⏭ desktop-tutorial  同期しない設定        │
│  …                                       │
│                                          │
│  ▸ くわしいログ（実行した Git コマンド）      │
└──────────────────────────────────────────┘
```

- 大きな「ぜんぶ同期」ボタンを置く。
- リポジトリごとに、結果を 1 行で表示する。
- 「くわしいログ」を開くと、実際に動いた Git コマンドと、その意味の日本語解説が見られる。Git の勉強用（**Claudeの判断**）。

### 5.2 同期の流れ（リポジトリ 1 つあたり）

ボタンを押したら、全リポジトリについて次の流れを 1 つずつ行う。

1. GitHub からリポジトリの一覧を取ってくる。
2. 手元にないリポジトリは**クローン**する。
3. 手元に変更があれば、LFS の対象かを確認してから**コミット**する。
4. **フェッチ**して、GitHub 側の新しい変更を確認する。
5. GitHub 側に新しい変更があれば、手元の変更と合体させる（**マージ**）。
   - うまく合体できたら → 次へ進む。
   - **競合**したら → そのリポジトリは「競合あり」で止める。合体は途中でやめて、競合する前の状態に戻す。その後の扱いは 5.4 の手順に従う。
6. **プッシュ**する。

- 1 つのリポジトリで失敗しても、記録だけ残して次のリポジトリに進む。
- **（Claudeの判断）** 合体の方法は「マージ」にする。もう 1 つの方法の「リベース」は履歴を書きかえるので、初心者には事故が起きたときに戻しにくい。

### 5.3 コミットメッセージ

自動で付ける（**Claudeの判断**）。

例：`[peers Sync] DESKTOP-ABC から同期 (2026-11-27 14:32) — 3 個のファイル`

これで、どのパソコンでいつ行った作業なのかが、あとから GitHub 上で分かる。

### 5.4 競合したとき

競合とは、2 台のパソコンで同じファイルを別々に変えてしまった状態のこと。このときは、どちらも消さないことを最優先にする（**Claudeの判断**）。

- **まず Git に自動で合体させる。** 同じファイルでも、変えた場所が違えば Git が自動で合体できる。ユーザーに選んでもらうのは、本当にぶつかったファイルだけ。
- **テキストファイル（コード・`.md`）が本当にぶつかった場合**
  - 同期の途中では止めない。そのリポジトリを「競合あり」にして、次のリポジトリへ進む。合体は途中でやめて、競合する前の状態に戻す（5.2 の 5）。
  - あとでユーザーが「確認する」を押したときに、もう一度合体をやり直す。そのうえで、ファイルごとに「このパソコンの版」と「GitHub の版」を並べて見せ、どちらを残すか選んでもらう。
  - 選ばれなかったほうも、`ファイル名 (DESKTOP-ABC の版).md` のような名前で残す。これで作業は消えない。
  - 変更部分ごとに選べる本格的な合体画面は作らない（将来の候補）。
- **画像・動画など（中身を比べられないファイル）の場合**
  両方とも残す。GitHub の版は元の名前のまま、このパソコンの版は `ファイル名 (DESKTOP-ABC の版).mp4` という名前で保存する。そのうえで同期を完了させる。

### 5.5 大きいファイル（Git LFS）

**（Claudeの判断）**
- 次のファイルは自動で LFS の対象にする。
  - 動画の拡張子（`.mp4` `.mov` `.avi` `.mkv` `.webm` など）
  - 拡張子に関係なく、50MB を超えるファイル
- 画像は、50MB を超えるとき以外は普通の Git で扱う。
- LFS のルールは、**これから新しく追加するファイルにだけ**使う。すでに普通の Git に入っている動画はそのままにする。勝手に LFS に移すと、無料枠 10GB を一度に使い切るおそれがあるため。
- LFS の対象にするには `.gitattributes` という設定ファイルに書き込む必要がある。これはアプリが自動で行う。
- 2GB を超えるファイルは GitHub に送れない。そのファイルは同期の対象から外し、画面で警告する。
- その日に送る LFS ファイルの合計が大きい（目安 1GB 以上）ときは、同期を始める前に「無料枠を使い切るかもしれません」と確認する。

### 5.6 リポジトリを置く場所

**（Claudeの判断）**
- Windows では `C:\Users\<名前>\GitHub\`、Mac では `~/GitHub/` の中に、全リポジトリを並べて置く。
- 置き場所は設定画面で変えられる。
- すでに別の場所にクローン済みのリポジトリがあれば、設定画面からその場所を登録できる。

### 5.7 設定画面

- GitHub へのログイン / ログアウト
- リポジトリを置く場所
- 同期しないリポジトリの選択（例：desktop-tutorial を外す）
- このパソコンの名前（コミットメッセージに入る）

### 5.8 GitHub へのログイン

- ユーザーにトークンをコピーして貼ってもらうような、むずかしい手順にはしない。
- 「GitHub でログイン」ボタンを押すと、ブラウザが開いてログインできる仕組みにする。
- ログイン情報は、パソコン標準の安全な保管場所に保存する（Windows は資格情報マネージャー、Mac はキーチェーン）。

## 6. 作る人に任せること

- **使う言語とライブラリ**
  条件は 3 つ。Windows と Mac で動くこと、配布用の `.exe` / `.app` が作れること、初心者があとからコードを読んで学べること。（**Claudeの判断** としては、Python と Python で画面を作るライブラリの組み合わせを第一候補にしている。）
- **Git の動かし方**
  パソコンに入っている `git` コマンドを呼び出すか、Git 用のライブラリを使うか。
- **ブラウザでログインする仕組みの具体的なやり方**
  例：GitHub の「デバイスフロー」、GitHub CLI を利用する、など。
- **配布ファイルの作り方**
  例：GitHub Actions で Windows 用と Mac 用を自動で作る。
- **テストのやり方**
  本物の GitHub を使わずに、手元に作った練習用リポジトリで同期・競合・LFS を確かめる方法。

## 7. 将来の追加候補（今回はやらない）

- パソコンを起動したときや一定時間ごとに、自動で同期する。
- 新しいフォルダから、GitHub のリポジトリを新しく作る。
- 動画だけをクラウドドライブに逃がす（B 案への拡張）。
- LFS の使用量を表示する。
